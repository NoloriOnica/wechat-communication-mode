# Repository Structure and Running the Prototype

## 1. Repository Structure

The repository follows the standard layout of a Vite and React project. The root directory contains the project
configuration, while all application code is located in the `src` directory.

| Path | Description |
| --- | --- |
| `index.html` | The HTML entry point, which loads the typefaces and the application script. |
| `package.json` | Project metadata, dependencies and the available commands. |
| `vite.config.js` | Build configuration, including the React plugin and relative asset paths. |
| `src/main.jsx` | Mounts the React application into the page. |
| `src/App.jsx` | Routing logic and the three views: the start page, the scenario player and the frame view. |
| `src/Phone.jsx` | Renders a 393 × 852 screen at any scale, either interactively or as a thumbnail. |
| `src/scenarios.js` | Definitions of the seven scenarios, including their steps and instructions. |
| `src/screens/screens.jsx` | The eighteen screens, their prototype links and their captions from Figma. |
| `src/screens/bases.jsx` | The Home, Contact and Chat base layouts shared by the screens. |
| `src/components/ui.jsx` | Design tokens and shared interface components, such as buttons, the navigation bar, banners and guide cards. |
| `src/components/iconPaths.js` | The twenty-four icons exported from Figma as SVG path data. |
| `src/assets/` | Contact photographs and the status bar image. |
| `src/styles.css` | Global styles for the page layout, device frame and animations. |
| `dist/` | The production build, generated by the build command and excluded from version control. |

## 2. Prerequisites

Running the prototype requires **Node.js version 20.19 or later** (or 22.12 or later), which is the minimum
supported by Vite 8, together with npm, which is installed with Node.js.

## 3. Running the Prototype Locally

From the root of the repository, install the dependencies once and then start the development server:

```bash
npm install
npm run dev
```

The prototype is then available at `http://localhost:5173`, and any change to the source code is reflected in the
browser immediately.

To test the prototype on a mobile phone, connect the phone to the same Wi-Fi network as the computer and start the
server with `npm run dev -- --host`. The command prints a network address, which can be opened in the phone's
browser.

## 4. Building and Deploying

A production version of the prototype is created with:

```bash
npm run build
```

This produces a static website in the `dist` directory. The build can be checked locally with `npm run preview`.
Because the build uses relative paths, the contents of `dist` can be uploaded without modification to any static
hosting service, such as GitHub Pages, Netlify or Vercel, or served from a subfolder of an existing website.

## 5. Using the Prototype

The **start page** presents the seven scenarios and a gallery of all eighteen screens. Selecting a scenario opens
the **scenario player**, where the user can progress by tapping the buttons on the simulated phone, as they would in
the real application. Alternatively, the Back and Next buttons, the step list or the left and right arrow keys can
be used. Tapping an area that is not interactive briefly highlights the tappable areas, and the option *Show
tappable areas* keeps them visible.

Individual steps can be shared using links of the form `#/play/<scenario>/<screen>`, for example
`#/play/video-call/02`. A single screen can be displayed at its original size using `#/frame/<screen>`, for example
`#/frame/05`, which is useful for comparing the implementation with the Figma design.

## 6. Modifying the Prototype

Scenarios can be added or edited in `src/scenarios.js` by changing their list of screens and instructions; no
interface code needs to change. Individual screens are defined as functions named `S01` to `S18` in
`src/screens/screens.jsx`, while layouts shared by several screens are located in `src/screens/bases.jsx`. Colours,
typefaces and shared components are defined in `src/components/ui.jsx`, and changes made there apply to every
screen.
